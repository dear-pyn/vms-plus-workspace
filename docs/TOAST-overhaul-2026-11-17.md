# Toast + Notification Overhaul — ตามชีต "MaintainD-Overhaul - OH-Toast (ทุกหน้า)"

เจ้าของงานส่ง 17 พ.ย. 2569 · ข้อความทั้งหมดอยู่ที่ `domains/overhaul/features/shared/messages.ts` (T = toast · N = notification) อ้างเลขแถวของชีต

กติกาที่ใช้
- ข้อความ = คอลัมน์ "ข้อความ toast" ที่ลูกค้า CF หรือ NOTE BY PEACE ให้ปรับ
- แถวที่มีคอลัมน์ "New toast" → toast แสดง New toast อย่างเดียว (เจ้าของงาน 17 พ.ย. 2569 "แยกกัน toast new กับ noti") · Error แสดง Status Code เป็นข้อความรอง
- Notification แยกจาก toast: ตามคอลัมน์ "ข้อความ notification" ("ตาม Toast เลย" = ข้อความคอลัมน์ toast) · {overhaul ระบบ xxx} = Overhaul + ชื่อ PO + {PO (ทะเบียน)}
- {ข้อมูลสำคัญ เช่นเลขแผนหรือ PO}: ระดับแผน = เลขแผน · งานรายคัน = `เลข PO (ทะเบียน)`
- General Error = Status Code `500 Internal Server Error`

Notification สร้างจากข้อมูลงาน แสดงเฉพาะเหตุการณ์ 3 วันล่าสุด · ไม่มี login แยกคน จึงบอกปลายทางในบรรทัดเวลา ("ถึง …")

ยังไม่เคาะ
- แถว 25: NOTE ให้ "ปิดงาน {…} เรียบร้อยแล้ว" (เขียนตอนตัดผู้อนุมัติ) — ตอนนี้มีผู้อนุมัติ จึงใช้ "คำขอปิดงาน … รอการตอบรับ" และย้าย "เรียบร้อยแล้ว" ไปแถว 27
- แถว 26: คอลัมน์ปลายทาง "ส่งให้ กบค. กรย. และหน่วยงาน" แต่เป็นเคสบันทึกไม่สำเร็จ — ไม่ส่ง notification
- แถว 16 · 29 ใช้โทน warning (ชีตระบุ "ไม่สำเร็จ" แต่ไม่ใช่ error ของระบบ)
- ข้อความที่ไม่มีในชีตยังคงเดิม: แก้ไขผู้อนุมัติสำเร็จ · เพิ่ม/แก้ไขอะไหล่สำเร็จ · เพิ่มยานพาหนะเข้าแผน · ระบุราคา

Notification อื่นในกระดิ่งที่ไม่ได้มาจากชีตนี้: แจ้งวันสิ้นสุดประกัน (FigJam Q.1–Q.5) · ส่งมอบยานพาหนะคืนหน่วยงาน (ขั้น 5 ไม่มีการนัดหมาย · เจ้าของงาน 16 พ.ย. 2569)
— ปรับให้ตามรูปแบบชีต 17 พ.ย. 2569: ใช้ `{PO (ทะเบียน)}` (เดิมเป็น ทะเบียน (PO)) · ปลายทางอยู่บรรทัดเวลา ("ถึง กบค." / "ถึง {ผู้รับมอบรถ} (หน่วยงาน {สังกัด})") · ข้อความอยู่ที่ `N.warrantyEnd` · `N.returned`
