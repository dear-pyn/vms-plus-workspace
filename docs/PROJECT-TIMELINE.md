## ประเด็นที่พบ

1. **เลข JO ยังไม่สอดคล้อง:** แถว Fleet Card ใช้ JO3 แต่แถวรวม 100 เขียน “รวม JO4”; กลุ่ม JO2 แถวรวม 88 เขียน “รวม JO2–3” ต้องยืนยันเลขใบสั่งงานจริงก่อนเชื่อมการ์ด
2. **ยอด MD ยังใช้คำนวณไม่ได้:** ชื่อชีต/หัวเรื่องระบุ 1,790 แต่แถวคำอธิบายและตารางราคาบางส่วนระบุ 1,760; M102 มี cached `#REF!` จาก external workbook และ M101 cached 82 ไม่ตรงหัวเรื่อง ต้องตรวจสูตรและคำนวณใหม่ก่อนใช้ถ่วงน้ำหนัก progress
3. **วันเริ่มเป็นสมมติฐาน:** คำอธิบายระบุจันทร์แรก ส.ค. 2569 แต่ C3 ว่าง ยังไม่แปลงสัปดาห์เป็นวันส่งจริง
4. **Card UC กับ Timeline UC ไม่เท่ากันเสมอ:** เช่นแถว UC01 อ้างการ์ด 1.1.8 และ 1.2.14; UC16 อ้าง 1.1.11 และ 1.2.6 จึงต้องมี mapping รหัสการ์ดเดิม → UC timeline แยก ไม่ parse เลขแล้วจับคู่ทันที
5. **Progress มีหลายความหมาย:** แผนระบุสูตรเมื่อ scope ครบ `70% + 30% × test pass ratio`; งานบางส่วนประเมินตาม scope จึงไม่เท่ากับลูกค้ายืนยัน UI หรือส่งมอบแล้ว
6. **ตัวเลขว่างคือยังไม่มีข้อมูล:** JO2/JO3 มี progress ว่าง ไม่ตีความว่า 0% หรือยังไม่เริ่มโดยอัตโนมัติ
7. **งานปิดงวดแยกจาก UC ตัวเลข:** PRE/DEP/POST ครอบคลุมทดสอบ/security, deploy และคู่มือ/KT ต้อง track เพิ่มโดยไม่เดาเลข UC ให้เอง

## ใช้ต่อใน Workspace

- รหัสการ์ดตามที่ตกลง: `[PEA-1.2.13]` ไม่มีศูนย์นำหน้า; running แยกตาม JO + UC และไม่ใช้ซ้ำ
- เก็บ card ID/URL, รหัสเดิม, timeline UC และ JO ที่ยืนยันแยกกัน เพื่อรักษาการ์ดเก่าที่เลขไม่ตรง
- โครงเชื่อม: `JO ↔ UC ↔ Trello card ↔ case/revision ↔ screen ↔ Figma/FigJam/AC`; ไม่สร้าง domain ซ้ำตาม JO
- แยก progress งานออกแบบ/การยืนยัน, progress พัฒนา/SIT และสถานะส่งมอบ
- ถ้ามี dependency เช่นข้อมูลรถ → แผน → บันทึกงาน → รายงาน ให้บันทึกเป็นข้อเสนอและตรวจจาก requirement ก่อนกำหนดเป็นเงื่อนไขบังคับ
- ขั้นต่อไปก่อน import: ยืนยันไฟล์ต้นทาง, เลข JO จริง, mapping การ์ดเก่า และฐาน MD; ยังไม่เปลี่ยนรหัสหรือ import อัตโนมัติ
