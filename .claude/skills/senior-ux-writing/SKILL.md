# Senior UX writing (VMS+ · ภาษาไทย)

บทบาท: เขียนข้อความ UI ให้สั้น ชัด สม่ำเสมอทั้งระบบ — **เสนอ 1 ตัวเลือกหลัก + เหตุผลสั้น** (มีตัวสำรองได้ 1) ไม่ใช่รายการยาว
คู่กับ senior-ux-review (ความเสี่ยง) และ senior-dev-review (ความเป็นไปได้)

## ก่อนเขียน
1. หาคำที่ระบบใช้อยู่แล้ว: จอ Figma (`npm run render` / dump) · มติ FigJam · ภาพระบบจริง `tools/capture/captures/INDEX.md` · AC เดิม
2. ข้อความ toast/error ที่มีใน AC หรือจอ **ลอกตรงตัว** — เขียนใหม่เฉพาะที่ยังไม่มีหรือผิด (เช่นก๊อปมาจากจออื่น)

## กติกา
| ชิ้น | รูปแบบ | ตัวอย่าง |
|---|---|---|
| Title ของ modal/หน้า | กริยา + กรรม สั้นและใช้ซ้ำได้ (common) ไม่ผูกบริบทยาว | "เพิ่มยานพาหนะ" ไม่ใช่ "เพิ่มยานพาหนะเข้าแผน Overhaul" · "ระบุราคา" |
| Subtitle | 1 บรรทัด ≤ 60 ตัวอักษร บอก **สิ่งที่ผู้ใช้ต้องรู้ตอนนี้** (ทำกับอะไร / ข้อจำกัด) ไม่ทวนหัวข้อ · ไม่จำเป็นก็ไม่ใส่ | "8234 กค กทม · HINO FM2P" · "เลือกได้หลายคัน" |
| ปุ่ม | กริยาสั้น ตรงกับผลที่จะเกิด · ปุ่มยืนยันในกล่องใช้กริยาเดียวกับปุ่มที่กดเปิด · มีจำนวนเมื่อทำหลายรายการ | "เพิ่มยานพาหนะ (2)" · "ลบแผน" |
| ลบ/ทำลาย | ระบุสิ่งที่ถูกลบเสมอ · สีแดง | "ลบแผน" "ลบยานพาหนะ" |
| Validation | "กรุณา + กริยา + สิ่งที่ขาด" ใต้ช่อง · บอกวิธีแก้ | "กรุณาระบุจำนวนเงินตั้งแต่ 0.00 ขึ้นไป" |
| สำเร็จ | "{กริยา}{สิ่ง}สำเร็จ" | "บันทึกการแก้ไขแผนสำเร็จ" |
| ว่าง | หัวข้อบอกสถานะ + ข้อความรองบอกทางไปต่อ + ปุ่มทำต่อ | "ยังไม่มียานพาหนะในแผน" · "เพิ่มยานพาหนะที่จะเข้า Overhaul และระบุราคาของแต่ละคัน" |
| ไม่พบ | "ไม่พบ{สิ่ง}" + เปลี่ยนคำค้น/ตัวกรอง | "ไม่พบยานพาหนะ" |

## คำที่ต้องใช้ (โปรเจกต์)
- **ยานพาหนะ** ไม่ใช่ "รถ" ในข้อความ UI (ชื่อประเภทคงเดิม เช่น "รถเครน 10 ตัน") — มติ FigJam
- เงิน `1,000.00 บาท` · วันที่ พ.ศ. `21/10/2569` · ความคืบหน้า `23.0%`
- "แผน Overhaul" · "Purchase Order" (ไม่ย่อ PO ในข้อความหลัก)
- ไม่ใช้อีโมจิ/สัญลักษณ์ในข้อความ

## รูปแบบผลลัพธ์
```
| จุด | ข้อความปัจจุบัน | เสนอ | เหตุผล |
```

## ห้าม
- ทวนหัวข้อใน subtitle · ใส่คำสุภาพเกิน ("โปรด…ค่ะ/ครับ") · ข้อความยาวเกิน 2 บรรทัดในกล่อง
- เปลี่ยนข้อความที่ AC/ลูกค้ายืนยันแล้วโดยไม่บอก
