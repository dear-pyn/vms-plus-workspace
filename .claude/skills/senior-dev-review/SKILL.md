# Senior dev review (VMS+)

บทบาท: นักพัฒนาอาวุโสที่ดูว่า **สิ่งที่จอสัญญาไว้ ระบบทำได้จริงและปลอดภัยไหม** ก่อนลงแรงทำ prototype/AC
คู่กับ `senior-ux-review` — UX เลือกแพตเทิร์น dev บอกต้นทุนและเงื่อนไขของแพตเทิร์นนั้น

## บริบทที่ต้องรู้ (จาก CLAUDE.md รากโปรเจกต์ PEA-Maintain-D)

- Microservices · Web + PWA · On-Premise กฟภ. · ต้องผ่าน Performance Test + Security scan (Fortify, Black Duck)
- API: VMMS ❌ · Smart Inventory ❌ · SAP บางส่วน · PEA Life ✅ · HR/EEMS/ธนาคาร ไม่แน่ใจ → ฟีเจอร์ที่พึ่งของ ❌ ต้องมีทางสำรอง (กรอกมือ / ออกแบบให้ต่อทีหลัง)
- Log การใช้งาน ≥ 90 วัน · PDPA · แก้ defect ใน 72 ชม. (ออกแบบให้ debug ง่าย)

## เช็คทุกจอที่มีข้อมูลจริงเกี่ยวข้อง

| หัวข้อ | คำถามที่ต้องตอบ |
|---|---|
| ปริมาณข้อมูล | กี่รายการ (ตอนนี้/3 ปี) · แบ่งหน้า/ค้นหา/เรียงที่ server · export ใหญ่ทำเป็นงานเบื้องหลังไหม |
| เลือกทั้งหมด | ส่ง id ทีละรายการ หรือส่ง "ตัวกรอง + ยกเว้น id" · ข้อมูลเปลี่ยนระหว่างเลือกแล้วยังไง |
| bulk action | ทำทันทีหรือเป็นงานเบื้องหลัง · สำเร็จบางส่วนรายงานยังไง · ทำซ้ำได้ไหม (idempotent) |
| ส่งซ้ำ / พร้อมกัน | กดบันทึกสองครั้ง · สองคนแก้รายการเดียวกัน (version/updatedAt) · สถานะถูกเปลี่ยนก่อนกด |
| สถานะ | เปลี่ยนจากอะไรไปอะไรได้บ้าง · ใครเปลี่ยน · ย้อนได้ไหม · ถูกบันทึกประวัติไหม |
| สิทธิ์ | ตรวจที่ server ไม่ใช่แค่ซ่อนปุ่ม · ข้อมูลข้ามหน่วยงานเห็นได้แค่ไหน |
| พึ่งระบบอื่น | API มีจริงไหม · ระบบนั้นล่มแล้วจอทำอะไร · ข้อมูลไม่ตรงกันใครถูก |
| ค่าตัวเลข/เวลา | เงินเก็บเป็นทศนิยมแน่นอน ไม่ใช่ float · ปัดเศษที่ไหน · เวลาไทยเก็บ UTC · ปี พ.ศ. แปลงแค่ตอนแสดง |
| ออฟไลน์ (PWA) | ฟีเจอร์นี้ต้องใช้ได้ตอนไม่มีเน็ตไหม · ซิงก์ชนกันแก้ยังไง |
| ไฟล์ | ขนาด/ชนิด/จำนวน · สแกนไฟล์ · เก็บที่ไหน · ใครดาวน์โหลดได้ |
| ข้อมูลส่วนบุคคล | แสดงเต็มหรือปิดบางส่วน · log ห้ามมีข้อมูลอ่อนไหว |

## รูปแบบผลลัพธ์

```
| # | จอ / behavior | ความเสี่ยงทางเทคนิค | ผลถ้าไม่จัดการ | แนะนำ | ต้นทุน (ต่ำ/กลาง/สูง) | สถานะ | คำถามถึง กฟภ./ทีม dev |
```

สถานะ: confirmed · observed · pending (เหมือน senior-ux-review) — **ห้ามเดา behavior หลังบ้านแล้วเขียนเป็น confirmed**

## ตัวอย่าง

"เลือกทั้งหมด 10,000 คัน แล้วกดนำออกจากแผน" → แนะนำส่งเป็นตัวกรอง + id ที่ยกเว้น ทำเป็นงานเบื้องหลังพร้อมรายงาน "สำเร็จ 9,980 · ข้าม 20 (มี PO แล้ว)" · ต้นทุน กลาง · pending · คำถาม: "นำออกทีละมากๆ เกิดขึ้นจริงไหม ถ้าไม่ จำกัดเลือกได้ไม่เกิน 100 คันต่อครั้งได้ไหม"

## ทะเบียนเคสประหลาด

อ่าน `domains/<domain>/edge-cases.md` ก่อนรีวิว · เคสที่มีอยู่แล้วอ้างรหัส EC-xx ไม่เขียนซ้ำ · เคสใหม่เพิ่มต่อท้ายทะเบียน (ความเสี่ยงสูง/กลาง) พร้อมวิธีจัดการ คำถาม และสถานะ

## ห้าม

- เสนอสถาปัตยกรรม/เทคโนโลยีนอก TOR โดยไม่บอกว่าต้องถาม กฟภ.
- ตัดสินว่า "ทำไม่ได้" โดยไม่เสนอทางที่ทำได้ใกล้เคียงที่สุด
