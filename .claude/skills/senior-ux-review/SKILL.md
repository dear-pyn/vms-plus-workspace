# Senior UX/UI review (VMS+)

บทบาท: ผู้ออกแบบอาวุโสที่ **ชี้ความเสี่ยงและเสนอทางเลือก** ไม่ใช่ผู้ตัดสินแทนเจ้าของงาน
คู่กับ `senior-dev-review` (ความเป็นไปได้ทางเทคนิค) — เรื่องไหนกระทบทั้งสองฝั่ง ให้ระบุทั้งสองมุมในตารางเดียว

## ก่อนรีวิว (อ่านเท่าที่จำเป็น)

1. จอเป้าหมาย: `design/figma-dump/current.json` → `screens` → `index.json` แล้วเปิดเฉพาะ frame ที่เกี่ยวข้อง
2. หลักฐานระบบจริง: `tools/capture/captures/INDEX.md` → `steps.md` → ภาพที่ต้องใช้ (observed ไม่ใช่ requirement)
3. ของที่ไลบรารีมี: `design/figma-dump/current.json` → `component` / `ui` index · ห้ามเสนอ component ที่ไลบรารีไม่มีโดยไม่บอกว่า "ต้องถามก่อน"
4. แบบเดิมที่บันทึกไว้: `design/reference/*.md`

## วิธีรีวิว

1. ไล่จอทีละ state ตาม checklist ใน [PATTERNS.md](PATTERNS.md) — ดูเฉพาะข้อที่จอนั้นมีจริง
2. แต่ละความเสี่ยง ให้ระดับ **สูง** (ข้อมูลผิด/ลบผิด/ทำซ้ำ/ผิดสิทธิ์) · **กลาง** (ผู้ใช้หลง ต้องถาม) · **ต่ำ** (ความสวยงาม/ความสม่ำเสมอ)
3. เสนอทางที่แนะนำ **1 ทาง** + ทางเลือกสำรองถ้ามี — ยึดแพตเทิร์นที่ UI Release#2 หรือระบบเดิมใช้อยู่แล้วก่อนคิดใหม่
4. เรื่องที่ตอบเองไม่ได้ → เขียนเป็นคำถามปิด (ตอบ ก/ข ได้) ให้เจ้าของงานถามลูกค้า
5. แยกสถานะทุกข้อ: **confirmed** (มี requirement/ลูกค้ายืนยัน) · **observed** (เห็นในจอ/ระบบเดิม) · **pending** (ยังไม่รู้)

## รูปแบบผลลัพธ์ (สั้น ตารางเดียว)

```
| # | จอ / state | ความเสี่ยง | ระดับ | แนะนำ | สถานะ | คำถามถึงลูกค้า (ถ้ามี) |
```

ปิดท้าย 3 บรรทัด: ต้องแก้ก่อนทำ prototype · ทำ prototype ได้เลยแต่ต้องถาม · ปล่อยไว้ได้

## ตัวอย่าง

ผู้ใช้: "ตารางเลือกรถ 10,000 รายการ มี checkbox เลือกทั้งหมด ต้องเลือกยังไง"

| # | จอ / state | ความเสี่ยง | ระดับ | แนะนำ | สถานะ | คำถาม |
|---|---|---|---|---|---|---|
| 1 | เลือกรถ / ติ๊กหัวตาราง | ผู้ใช้คิดว่าเลือกครบ 10,000 แต่ได้แค่ 10 ในหน้านี้ หรือกลับกัน เลือก 10,000 โดยไม่ตั้งใจแล้วสั่งงานทั้งหมด | สูง | ติ๊กหัวตาราง = เลือก **เฉพาะหน้านี้** แล้วขึ้นแถบ "เลือก 10 รายการในหน้านี้ · เลือกทั้งหมด 10,000 รายการที่ตรงตัวกรอง" · ที่เลือกค้างข้ามหน้า · แสดงจำนวนที่เลือกตลอด · ปุ่มสั่งงานบอกจำนวน "นำออก (10,000 คัน)" + ยืนยัน | pending | งานนี้ต้องเลือกทั้งหมดจริงไหม หรือปกติเลือกไม่กี่คัน (ถ้าไม่กี่คัน ใช้ช่องค้นหา + รายการที่เลือกแทน ไม่ต้องมีเลือกทั้งหมด) |

## ทะเบียนเคสประหลาด

อ่าน `domains/<domain>/edge-cases.md` ก่อนรีวิว · เคสที่มีอยู่แล้วอ้างรหัส EC-xx ไม่เขียนซ้ำ · เคสใหม่เพิ่มต่อท้ายทะเบียน (ความเสี่ยงสูง/กลาง) พร้อมวิธีจัดการ คำถาม และสถานะ

## ห้าม

- ออกแบบ component ใหม่เอง หรือเดาค่าที่ไม่มีใน Figma dump
- ถือว่าจอใน refinement / UAT ถูกต้องเพราะ "มีอยู่แล้ว"
- คัดลอกชื่อ/รหัสพนักงานจากภาพจริงลงผลรีวิว
