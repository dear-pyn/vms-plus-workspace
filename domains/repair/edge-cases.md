# Repair (แจ้งซ่อม/งานซ่อม) — ทะเบียนเคสประหลาด (Edge cases)

ใช้ร่วมทุกจอของงานซ่อม · senior-ux-review / senior-dev-review อ่านก่อนรีวิว แล้วเพิ่มเคสใหม่ต่อท้าย (รหัสไม่ใช้ซ้ำ)
สถานะ: **pending** = รอตอบ · **confirmed** = ยืนยันแล้ว (ผู้ยืนยัน/วันที่) · **done** = ทำในต้นแบบแล้ว

| รหัส | เคส | เกิดที่ | วิธีจัดการ (แนะนำ) | สถานะ |
|---|---|---|---|---|
| EC-R01 | กบค. กด "ต้นทางยืนยัน" แทนหน่วยงาน — สถานะเปลี่ยนทันทีไม่มีกล่องยืนยัน (เกิดจริงบน UAT 20 พ.ย. 2569) | ขั้น 2, 5 | ให้ต้นทางยืนยันเอง หรือบันทึกผู้ยืนยันแทน + กล่องยืนยัน | pending · ต้นแบบ r2: เมนูตอบรับนัดหมายงานซ่อม · ปุ่มลัดเหลือเฉพาะ admin-super และบันทึกว่า "กบค. กดแทน" |
| EC-R02 | ผู้อนุมัติแต่ละขั้นต้องเลือกวิธีซ่อมใหม่ ค่าเดิมไม่ตั้งไว้ | รอหัวหน้าหน่วยงาน/หัวหน้า กบค. อนุมัติ | ตั้งค่าเดิม แสดงว่าใครเลือก | pending |
| EC-R03 | ยอดคงคลังอะไหล่ไม่ตรง (Smart Inventory ไม่มี API) · เลือกเกินยอด | เลือกอะไหล่ | ส่วนเกินเป็นรายการจัดซื้อ · แสดงเวลาข้อมูลยอด | pending · ต้นแบบ: คำนวณเบิก/จัดซื้อแยก |
| EC-R04 | ออกจากหน้าระหว่างกรอกแจ้งซ่อม/ฟอร์มขั้น | แจ้งซ่อม · ขั้น 3, 6, 7 | ถามก่อนออก · ร่าง | done (แจ้งซ่อม) · pending (ฟอร์มขั้น) |
| EC-R05 | กดยืนยันซ้ำ / สองคนทำขั้นเดียวกัน | ทุกปุ่มเปลี่ยนสถานะ | ตรวจสถานะเดิมที่ server (optimistic lock) | pending (dev) |
| EC-R06 | role ไม่ตรงกับสถานะ (UAT ทดสอบด้วย admin-super) | ทุกหน้า | ตรวจสิทธิ์ที่ server ตามสถานะ | pending · ต้นแบบ: ตัวเลือก role + ปิดปุ่ม |
| EC-R07 | จำนวนที่ใช้ > จำนวนที่เบิก · จำนวนที่คืนติดลบ | ขั้น 6 | จำกัดจำนวนที่ใช้ ≤ ที่เบิก · คืน = เบิก − ใช้ | done (ต้นแบบ) |
| EC-R08 | ปิดงานทันทีโดยไม่มีเหตุผล / ปิดหลังเบิกอะไหล่แล้ว | ทุกขั้น | บังคับเหตุผล · อะไหล่ที่เบิกแล้วต้องคืนหรือบันทึก | pending · ต้นแบบ: บังคับเหตุผล |
| EC-R09 | ยานพาหนะคันเดียวกันมีใบแจ้งซ่อมค้างหลายใบ (UAT มีหลายใบ "รอหัวหน้าหน่วยงานอนุมัติ" ของคันเดียวกัน) | แจ้งซ่อม | เตือนตอนเลือกยานพาหนะ | pending |
| EC-R10 | หน่วยงานเลือกวันที่นอกช่วงที่ กบค. เสนอ | ตอบรับนัดหมาย | ปฏิทินจำกัดช่วง + ข้อความ "กรุณาเลือกวันที่ในช่วง …" · ถ้าไม่สะดวกให้ปฏิเสธพร้อมวันที่สะดวก | done (ต้นแบบ) |
| EC-R11 | ส่งคำขอเซ็นแล้วเปลี่ยนตัวผู้ส่งมอบรถ | ขั้น 3, 6 | ล็อกชื่อหลังส่งคำขอ · ยกเลิกคำขอก่อนเปลี่ยน | done (ต้นแบบ) · แบบ Overhaul: ส่งคำขอแล้วล็อกข้อมูลทั้งขั้น · ยังไม่เซ็นกด "แก้ไข" ยกเลิกคำขอได้ |
| EC-R12 | บันทึกความคืบหน้าแล้วต้องแก้/ลบ | ขั้น 4 | แบบ Overhaul (แก้ได้ไม่เปลี่ยนวันเวลา · ลบได้จนซ่อมเสร็จ) | pending · ต้นแบบ: เพิ่มได้อย่างเดียว |
| EC-R13 | ค่าซ่อมเกิน 30% แล้วกดเสนอเข้าแผน Overhaul / เสนอจำหน่าย — ข้อเสนอไปที่ใคร และงานซ่อมเดิมยังเดินต่อหรือหยุด | รายการ แท็บเกิน 30% | ต้นแบบ: บันทึกข้อเสนอในงาน + ประวัติ เท่านั้น ไม่หยุดงาน | pending |
| EC-R14 | UAT ให้หัวหน้าหน่วยงานเลือกวิธีซ่อม + รับงานซ่อม แต่มติใหม่ย้ายหน้านี้ไปที่ กบค รับเรื่อง | อนุมัติก่อนซ่อม | ต้องแจ้งทีม dev ว่าหน้าจอเดิมเปลี่ยนเจ้าของ | pending · ต้นแบบ: ทำตามมติ |
| EC-R15 | ประเมินค่าซ่อมซ้ำหลายจุด (ผู้แจ้งใส่ราคาอู่ · กรย. ประเมิน · กบค. ประเมิน) แล้วตัวเลขไม่ตรงกัน — ใช้ตัวไหนเทียบ 30% | อนุมัติก่อนซ่อม | เสนอ: ให้ผู้ที่จะซ่อมเป็นผู้ประเมิน (อู่ = ใบเสนอราคา · กรย. = ตอนเลือกซ่อมเอง · กบค. = ตอนรับงาน) · ใช้ตัวล่าสุด | pending |
| EC-R16 | ยกเลิกใบแจ้งซ่อมแล้วต้องซ่อมคันเดิมอีก | ไม่อนุมัติ | สร้างใบใหม่ · ใบเดิมคงไว้เป็นประวัติ | done (ต้นแบบ) |
